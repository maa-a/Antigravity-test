## 1-2. `appsscript.json` は何を設定しているのか

Apps Scriptプロジェクトの**設定ファイル**です。コードではなく、
「このアプリをどう動かすか」をGoogleに伝える宣言書にあたります。
普段は隠れていて、⚙ プロジェクトの設定でONにすると見えるようになります。

```json
{
  "timeZone": "Asia/Tokyo",
  "dependencies": {},
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "webapp": {
    "executeAs": "USER_DEPLOYING",
    "access": "DOMAIN"
  },
  "oauthScopes": [
    "https://www.googleapis.com/auth/script.external_request",
    "https://www.googleapis.com/auth/script.scriptapp",
    "https://www.googleapis.com/auth/spreadsheets",
    "https://www.googleapis.com/auth/drive"
  ]
}
```

| 項目 | 意味 |
|---|---|
| `timeZone` | 日時の基準。日本時間（出力ファイル名の日付などに影響） |
| `runtimeVersion: "V8"` | **必須。** `class` を使っているため、旧ランタイムでは構文エラーになります |
| `executeAs: "USER_DEPLOYING"` | アプリを**デプロイした人の権限**で動かす設定 |
| `access: "DOMAIN"` | **同じGoogle Workspaceドメインの人なら誰でも**開けます（下記参照） |
| `oauthScopes` | このアプリが使う**権限の申請リスト**（下記） |

### oauthScopes ＝ 権限の申請リスト（ここが最重要）

**ここに書いていない権限は、コードが正しくても実行時に拒否されます。**

| 権限 | 何に使っているか | 無いとどうなる |
|---|---|---|
| `script.external_request` | **Gemini APIへの通信** | AI解析が全滅（窓1・2・3・5） |
| `script.scriptapp` | Excel変換時の認証トークン取得 | 📘Excel出力がエラー |
| `spreadsheets` | スプレッドシートの作成・書き込み | 📗スプレッドシート出力がエラー |
| `drive` | Excel変換と一時ファイルの削除 | 📘Excel出力がエラー |

`oauthScopes` を書かなくてもAI解析が動く場合がありますが、これはGASが実行時に
コードを見て必要な権限を**自動推測している**ためです。この推測は取りこぼしがあり、
特に `DriveApp` と `ScriptApp.getOAuthToken()` を組み合わせるExcel出力で失敗しやすいので、
明示的に書いておくのが確実です。

### access（誰がURLを開けるか）の選択肢

| 設定値 | 意味 |
|---|---|
| `"DOMAIN"` | **同じGoogle Workspaceドメインの人だけ**（社内利用向け。本リポジトリの既定） |
| `"MYSELF"` | デプロイした本人のみ |
| `"ANYONE_ANONYMOUS"` | URLを知っていれば誰でも（請求書を扱うため非推奨） |

変更したい場合は該当行を書き換えて再デプロイするか、デプロイ画面の
「アクセスできるユーザー」からでも切り替えられます。

> 🔐 **Gemini APIキーはこのファイルには一切含まれません。**
> キーはスクリプトプロパティに保存されるため、コードにもマニフェストにも残りません。

> ⚠ 権限を追加した直後は、次にアプリを開いたときに**再承認画面**が出ます。正常な動作です。

## 3. 文字化けの原因と修正内容

請求書で文字化けが起きていた原因は、単一ではなく次の5つが重なっていました。

### ① CSVのクォート処理が無かった（最大の原因）
V7.00 は `row.join(",")` でCSVを組み立てていました。
請求書の摘要には「株式会社A, B支店」のようにカンマが入ることが多く、
その1文字で**列が丸ごと右にズレて**、金額欄に文字列が入り込み、
画面上は「文字化け」に見えていました。

→ `CsvUtil`（サーバー）と `Utils.csvRow`（画面）でRFC4180準拠のクォート処理を追加。
読み込み側も `split(',')` をやめ、クォート対応パーサ `Utils.parseCsv` に置き換えました。

### ② Geminiの応答を先頭パートしか読んでいなかった
`jsonRes.candidates[0].content.parts[0].text` としていたため、
請求書のように情報量が多く応答が複数パートに分割されると、
**JSONが途中で切れた状態**でパースされ、壊れた文字列が混入していました。

→ 全パートを連結するよう修正（`GeminiApiClient._extractText`）。
あわせて応答形式を `application/json` に固定し、Markdown枠の混入も防止しています。

### ③ ファイル形式の誤判定
`file.type || 'image/jpeg'` としていたため、MIMEが空のPDFやHEICを
**JPEG画像としてAIに送信**し、AIがバイナリを誤読していました。

→ 拡張子から正しいMIMEを判定し、非対応形式（Excel・CSVなど）は
その場でエラー表示して送信しないようにしました。

### ④ Shift-JISに存在しない文字
請求書に頻出する `①` `㈱` `Ⅲ` `～` `−` や絵文字はShift-JISに存在せず、
変換時に化けます。

→ `Utils.normalizeForSjis` で安全な文字に置換（`①`→`(1)`、`㈱`→`(株)` など）。
さらに画面右上に**文字コード切替（Shift-JIS / UTF-8 BOM付き）**を追加しました。
弥生・PCAのPC版へ取り込む場合はShift-JIS、Excelで開くだけならUTF-8が確実です。

### ⑤ 制御文字・化け跡の混入
Excel由来の `_x000D_`、制御文字、置換文字 `U+FFFD` がそのまま出力されていました。

→ `CsvUtil.sanitize` で除去し、改行は半角スペースに畳んで1明細1行を保証しています。

## 4. 窓5：PCA会計 仕訳変換窓の使い方

1. 窓5に請求書・領収書を**何枚でも**ドロップ（PDF・PNG・JPEG・WEBP・HEIC）
2. 「まとめてAI解析」を押すと1件ずつ順番に解析され、結果が下の表に**蓄積**されます
3. 表の上のボタンで **🏢 社内用** / **🏛 会計事務所用** を切り替え
4. **CSV / Excel / スプレッドシート**のいずれかで出力

> 直列処理にしているのは、同時実行するとGASの実行数制限とGemini APIのレート制限に
> 当たりやすいためです。1枚が失敗しても他の枚数の処理は止まりません。

### 出力レイアウト

**🏢 社内用**（いただいたPCA見本データ `24.LTR…2024.xlsx` の並びに合わせています）

先頭11列は見本と完全に同じ順序なので、社内財務管理表にそのまま貼り付けられます。

```
伝票日付, 伝票番号, 借方科目コード, 借方科目名, 借方補助コード, 借方補助名,
借方部門コード, 借方部門名, 借方税区分名, 借方金額, 摘要文,
大分類, 小分類, 取引先, 元ファイル名, 要確認メモ
```
- 伝票日付は見本にあわせ `20260105` 形式
- 消費税額が読み取れた場合、`191 仮払消費税等` の行が自動で追加されます（見本と同じ税抜経理の形）
- 「要確認メモ」は画面で確認するための列です。不要なら列ごと削除してから貼り付けてください

**🏛 会計事務所用**（PCA仕訳インポート想定・借方/貸方ペア形式）

```
伝票日付, 伝票番号,
借方科目コード, 借方科目名, 借方補助コード, 借方補助名, 借方部門コード, 借方部門名, 借方税区分名, 借方金額,
貸方科目コード, 貸方科目名, 貸方補助コード, 貸方補助名, 貸方部門コード, 貸方部門名, 貸方税区分名, 貸方金額,
摘要文
```
- 伝票日付は `2026/01/05` 形式
- 貸方の相手科目は **`420 未払金`** を既定にしています。変更する場合は
  `Code.gs` の `buildOfficeRows()` 内 `CREDIT_CODE` / `CREDIT_NAME` を書き換えてください
- 借方合計＝貸方合計になるよう行単位で対にしています

> ℹ️ いただいた見本は借方側だけを抽出した明細でしたので、**社内用はその並びを忠実に再現**し、
> **会計事務所用はPCAに取り込める貸借ペア形式**を新たに用意する、という切り分けにしました。
> 会計事務所側で指定の受入フォーマットがある場合は、その列順を教えていただければ合わせ込みます。

## 4-2. 画面レイアウト（V8.10で作り直し）

### 直した不具合
窓5（PCA会計）が設定パネルの下に隠れて、ドロップも入力もできない状態でした。

**原因**：設定パネルを `position: absolute` で画面右上に浮かせていたため、
窓が5枚になって折り返した時点で、窓5のカードの上に覆いかぶさっていました。
窓を増やすほど悪化する作りでした。

**対応**：レイアウトを次のように組み直しました。

| 箇所 | 変更前 | 変更後 |
|---|---|---|
| 設定パネル | 右上に絶対配置（カードに重なる） | **上部固定ヘッダー**内の**ポップオーバー**（押したときだけ開く） |
| 窓の並び | `flex` ＋ 固定幅260px | **CSS Grid の auto-fill**（画面幅に応じて列数が自動で決まる） |
| ログ | 窓と同じ列に並ぶカード | **全幅の折りたたみパネル**（窓ではないので分離） |

ヘッダーの設定は **🔑 APIキー / ⚙ 勘定科目マスタ設定 / 🤖 モデル / 💾 文字コード** の4つ。
ポップオーバーは、外側クリックと `Esc` でも閉じます。

### 窓の追加は「配列に1件足すだけ」

窓カードのHTMLは `index.html` の **`WINDOW_DEFS`** という配列から自動生成しています。
**EDI日報（売上）の窓を足すときは、この配列に1件追加するだけ**です。
HTMLの追記も、CSSの調整も、初期化処理の変更も要りません。

```js
{
  section: '売上（EDI日報）',            // 分類チップに表示される
  sectionDesc: 'EDI日報を売上仕訳に変換します。',
  type: 'edi',                          // DOMのid接尾辞（drop-edi / input-edi …）
  num: 6,                               // カード左上の番号
  kind: 'multi',                        // 'ai' | 'multi' | 'local'
  title: 'EDI日報 売上取込',
  subtitle: '(日報データ／複数まとめて1CSV)',
  accent: '#e11d48', titleColor: '#e11d48',
  accept: '.csv,.txt', multiple: true,
  label: '窓6(EDI日報)',
  dropLabel: '日報データをドロップ',
  clearLabel: '全消去',
  promptPlaceholder: '例: 店舗コードで部門を割り当てて、など',
  buttonLabel: 'まとめてAI解析'
}
```

`index.html` の `WINDOW_DEFS` の末尾に、**この内容をコメントアウトした状態で置いてあります。**
コメントを外し、`Code.gs` 側に処理を1つ追加すれば動きます。

`kind` の意味：

| kind | 挙動 | 例 |
|---|---|---|
| `ai` | ファイルを1枚選び、ボタンでAI解析 | 窓1・窓2・窓3 |
| `multi` | 複数枚をまとめてAI解析し、1つのCSVに蓄積 | 窓5（EDI窓もこれ） |
| `local` | サーバーを呼ばず、ドロップした瞬間にブラウザ内で変換 | 窓4 |

> 実行ボタンの色は `accent` から自動で決まるため、**窓を足してもCSSの追記は不要**です。
> 同じ `kind` の窓を2つ以上作っても、DOMのidが `type` ごとに分かれるので衝突しません。

### 検証
実際にブラウザ（Chromium）で描画して確認しています。

- 1600px / 1280px / 420px の3サイズで、**カード同士・ヘッダーとの重なりが0件**
- 全ドロップゾーンが**実際にクリック可能**（`elementFromPoint` で最前面判定）
- ポップオーバーを開いた状態でも、窓の操作が妨げられない
- **窓を6つに増やしても**重なり0・横スクロールなし・窓6のDOMが正しく生成される

## 4-3. プレビュー表は「プルダウンで選ぶ」

会計のコードを覚えていなくても入力できるよう、窓5のプレビュー表の主要な列を
**マスタからのプルダウン選択**にしました。手入力（ダブルクリック）も従来どおり使えます。

### プルダウンになる列

| 列 | 選択肢の出どころ |
|---|---|
| 借方／貸方 **科目コード**・**科目名** | PCA勘定科目マスタ |
| 借方／貸方 **補助コード**・**補助名** | 補助科目マスタ（**選んでいる勘定科目に紐づくものだけ**） |
| 借方／貸方 **部門コード**・**部門名** | 部門マスタ |
| 借方／貸方 **税区分名** | 税区分マスタ |
| **大分類**・**小分類**（社内用） | 社内管理科目マスタ |

金額・日付・摘要文は、これまでどおりダブルクリックで自由入力です。

### 連動する動き

- **コードと名称は連動** … `710004` を選べば `売上原価（評価減）` が自動で入ります（逆も同じ）
- **選択肢は「コード 科目名」で表示** … `710004 売上原価（評価減）` のように出るので、
  コードを知らなくても名前で選べます
- **補助科目は勘定科目に追従** … 勘定科目を変えると、補助科目の候補も入れ替わり、
  中身は一度クリアされます（前の科目の補助が残る事故を防ぐため）
- **小分類は大分類で絞られる** … 大分類「飲食」を選ぶと、小分類は飲食の科目だけになります

### 会計知識がない担当者向けの入力手順

**勘定科目コードを触る必要はありません。** 業務の言葉で分かる「大分類 → 小分類」を選ぶだけです。

```
大分類「飲食」を選ぶ
      ↓
小分類が飲食のものだけに絞られる → 「食材原価」を選ぶ
      ↓
マスタの紐付けに従って、借方科目コード「710001」と
科目名「売上原価（受注）」が自動で入る
```

同名の小分類（`版権元RY` など）も、**大分類とのペアで正しい科目に振り分けられます**。
飲食の版権元RY と 物販の版権元RY は、別のPCA科目に紐付けられます。

### 売上原価のように内訳が複数ある科目

`710001 売上原価（受注）` `710002 売上原価（見込）` … のように内訳が分かれている科目は、
**⚙ 勘定科目マスタ設定 → 🏛 PCA勘定科目** に登録すれば、そのままプルダウンに並びます。

1. マスタ設定を開き「🏛 PCA勘定科目」タブへ
2. **「➕ 行を追加」** で1件ずつ足すか、**「📋 Excelから一括貼り付け」** で
   勘定科目設定Excelの「コード / 科目名」列をまとめて取り込む
3. 「🏢 社内管理科目」タブで、社内の小分類をそれぞれの内訳コードに紐付ける
   （例：`飲食 / 食材原価` → `710001`、`物販 / 版権元RY` → `710003`）

これで、担当者は小分類を選ぶだけで正しい内訳コードが入ります。

> **マスタに無い値も消しません。** 手入力した値や旧データにマスタ外のコードが入っていた場合、
> 選択肢の末尾に `999999（マスタ外）` のように表示され、そのまま保持されます。
> 消えて気づかない、ということが起きないようにしています。

> 未設定のセルは**黄色いプルダウン**で表示され、`（未設定）` と明示されます。
> そのままCSVに出しても空欄になるだけなので、**分かる分だけ選んで出力**して構いません。

### プルダウンの表示（V8.11で修正）

ブラウザ標準のプルダウンは **▼の幅を制御できず、選択肢の文字と重なって読めなくなる**
問題がありました。次のように直しています。

- 標準の▼を消し（`appearance: none`）、**矢印を自前で描画**
- 右側に**矢印ぶんの余白（28px）**を確保し、文字が矢印の下に潜り込まないように
- 長い科目名は `710006 売上原価（…` のように**末尾を省略**して表示
  （選択中の値そのものは省略されません。CSVには全文が出ます）
- 矢印は `pointer-events: none` なので、**矢印の位置をクリックしても普通に開きます**
- 幅の制限は矢印を描く枠側に持たせ、セルが広いときに**矢印だけが離れて浮かない**ように

画面内のすべてのプルダウン（表のセル・マスタ設定・未確定リスト・ヘッダーの
モデル選択と文字コード選択）に同じ見た目を適用しています。

## 4-4. 一度出力したデータの「下に追加」する

請求書は後から届くため、**1回で全部を出力しきれない**という前提で3つの方法を用意しました。

### 方法① 同じ画面で追加解析する（いちばん簡単）

窓5にファイルを追加でドロップして「まとめてAI解析」を押すだけです。
**前の解析結果は消えず、下に積み重なります。** 出力し直せば全件入った1つのファイルになります。

- 「全消去」を押さない限り、明細は保たれます
- 伝票番号は表全体で通し番号になります

### 方法② 前回出力したファイルを読み込んで続きに追加する

**CSV / Excel(.xlsx) / Googleスプレッドシート のいずれからでも**読み込めます。

| 前回の出力形式 | 読み込み方 |
|---|---|
| CSV | **「📥 前回出力を読み込んで続きに追加（CSV / Excel）」** からファイルを選択 |
| Excel(.xlsx) | 同じボタンから選択（サーバー側で変換して読み込みます） |
| スプレッドシート | **「📗 スプレッドシートから読み込む」** からURLを貼り付け |

```
前回出力したCSV（4行）を読み込む
        ↓
表の上に読み込まれる（左端に緑の帯が付きます）
        ↓
新しい請求書を解析すると、その「下」に積まれる
        ↓
出力すると、前回分＋今回分がまとまった1つのファイルになる
```

- **伝票番号は前回の続きから振られます。** 前回が1〜2なら、今回は3から。
  既に出力済みの番号と重複すると、PCA側の取込で事故になるためです
- CSVのヘッダーを見て、**社内用／会計事務所用のどちらの形式かを自動判定**します
- 窓5で出力したCSVでない場合は、読み込まずにエラーを出します
- 読み込んだ行も**画面でそのまま編集できます**（プルダウンも効きます）
- 「✖ 読み込みを解除」で、今回分だけに戻せます
- Shift-JIS / UTF-8 のどちらで保存したCSVでも読み込めます

> Excelは、Driveに一時的にスプレッドシートへ変換してから読み込みます。
> **一時ファイルは読み込み後に必ず削除**されるため、Drive上には残りません。
> スプレッドシートは**1枚目のシート**を読み込みます。

### 方法③ 作業を自動保存して、翌日に続きから

**解析した明細はブラウザに自動保存されます。** 画面を閉じても、次に開いたときに

> 前回の作業が残っています（8/2 15:30 時点 ／ 明細 12 件）。続きから追加できます。
> 　[ ▶ 続きから再開 ]　[ 破棄する ]

という案内が出るので、「続きから再開」を押せば前回の状態に戻ります。

- 保存先は**利用者のブラウザ内だけ**です。サーバーやDriveには送信しません
- 別のPC・別のブラウザには引き継がれません
- 「全消去」を押すと保存内容も消えます
- 保存容量を超える場合は保存を見送り、ログでお知らせします（先にCSV保存を推奨）

### どれを使えばよいか

| 状況 | 方法 |
|---|---|
| その場で追加の請求書が出てきた | ① 追加ドロップ |
| 前回のファイルは既に会計事務所へ渡した／別途保管している | ② CSVを読み込んで続きに追加 |
| 今日はここまで、続きは明日 | ③ 続きから再開 |

> 💡 **おすすめは ③ ＋ 毎回上書き出力**です。表には常に全件が入っているので、
> 出力するたびに「全件入った最新版」が1つできます。ファイルを継ぎ足す手間も、
> 伝票番号の管理も不要になります。

## 5. 勘定科目マスタの設定（グレーアウト行の扱い）

画面右上の **「⚙ 勘定科目マスタ設定」** から、Excelの列をそのままコピー＆ペーストで登録できます。

| タブ | 貼り付ける列 | 用途 |

| 社内管理科目 | 大分類 / 小分類 / (任意)PCA科目コード / (任意)セクション | 社内用CSVの分類、AIへの選択肢 |

### グレーアウト行について
いただいた `勘定科目設定.xlsx` を確認したところ、
- `委員会勘定科目` シート … 328行中 **132行がグレーアウト**（＝196行が有効）
- `LTR勘定科目` シート … 327行すべてグレーアウトなし

でした。**グレーアウト行を削除してからコピーして貼り付けてください。**

> **79科目**を入れてあります。6桁体系へ移行される場合は、上記パネルから貼り替えてください。

## 5-2. あとから科目を設定していく（画面で1行ずつ編集）

**「最初は空欄で出しておいて、決まったものから足していく」**運用ができるよう、
マスタ設定を**表形式の編集UI**にしました。Excelを開かずにブラウザだけで完結します。

画面右上の **「⚙ 勘定科目マスタ設定」** を開くと、4つのタブがあります。

| タブ | 何を設定するか | ポイント |
|---|---|---|
| 🏢 **社内管理科目** | 社内の大分類/小分類 ↔ **PCA勘定科目の紐付け** | PCA科目は**プルダウン選択**。未設定の行は黄色く表示され、`（未設定 → 空欄で出力）` と明示されます |
| 🏛 **PCA勘定科目** | 会計事務所提出用の科目そのもの | PCA側で科目を新設したらここに足します |
| 📌 **社内の仕分けルール** | 取引先キーワード／摘要キーワード → 科目 | AIの判断より優先。**具体的なルールが勝つ**順で適用 |
| 🏬 **部門** | 部門コード / 部門名 | |

### できること
- **➕ 行を追加** … 社内にしか無い科目（例：型代）も、PCA側で新設した科目もいつでも足せます
- **削除** … 使わなくなった行を1件だけ消せます
- **🔍 絞り込み** … 科目名やコードで検索

- **📋 Excelから一括貼り付け** … 従来どおりの全件置換も残してあります（確認ダイアログ付き）

### 壊れたマスタが保存されない仕組み
保存前にサーバー側で必ず検証し、問題があれば**保存せずに理由を返します**。

- コード・科目名が空 → 保存を拒否

- 社内管理科目に無い科目を仕分けルールが参照している → 保存を拒否

## 5-3. 社内ルールは「使いながら育てる」

社内ルールがこれから決まる、という前提に合わせて、
**未確定だった明細からその場でルールを作れる**導線を用意しました。

### 運用の流れ

```
1. 窓5に請求書を落として解析
        ↓
2. 科目が判定できなかった明細は「空欄」で出力される（＝そのまま提出できる）
        ↓
3. 同じ画面の【🗂 科目が未確定の明細】に、その明細が自動で集まる
        ↓
4. 大分類・小分類をプルダウンで選び「ルールとして保存」を押す
        ↓
5. 【🔄 マスタを反映して再判定】を押すと、読み込み済みの明細に即反映
        ↓
6. 次回以降、同じ取引先・摘要は自動で仕分けされる
```

### 未確定リストの中身
- **同じ「取引先＋摘要」はまとめて1行**に集約し、**件数の多い順**に並びます
  → よく出るものから設定していけば、少ない手数で自動化率が上がります
- 件数・合計金額・元ファイル名・**未確定だった理由**が並びます
  （「勘定科目が判定できませんでした」「PCA勘定科目が未紐付け」「小分類が複数の大分類に存在するため確定できません」など）
- ルールの条件は**「取引先」と「摘要」の両方に候補が入った状態**で表示されます
  → 不要なほうを空にしてから保存してください（空＝その条件を問わない）
  → 両方残したままなら「両方に一致したときだけ適用」となり、もっとも安全です

### 🔄 再判定はAIを呼びません
再判定は、解析時にAIが返した生データを各明細に保持しておき、
**マスタだけを当て直す**方式です。

- **APIの追加料金が発生しません**
- **待ち時間がほぼゼロ**です（何十枚読み込んでいても一瞬）
- 請求書を読み込み直す必要もありません

> ⚠ プレビュー表を手修正したあとに再判定・出力形式の切替を行うと、手修正は元に戻ります。
> その場合は確認ダイアログが出ますので、そこで中止できます。

## 5-4. もっと良い運用（ご提案）

上記に加えて、こういう進め方をおすすめします。

### ① 最初の1か月は「空欄のまま出す」を正とする
科目を無理に埋めるより、**空欄で出して経理側で埋める**ほうが結果的に速いです。
埋めた実績が未確定リストに溜まるので、それを見ながらルール化すれば、
**実際に発生した取引だけ**にルールを作れます（使わないルールを作らずに済む）。

### ② ルールは「取引先」と「摘要」を使い分ける

仕分けルールには **「取引先キーワード」** と **「摘要キーワード」** の2つの条件があり、
どちらか一方だけでも、両方でも指定できます。

| 使い方 | 適用範囲 | こんなときに |
|---|---|---|
| **摘要だけ** 入力 | 取引先を問わず、摘要にその語があれば適用 | 摘要に内容が書かれている請求書。`画稿費` `施工` `装飾` など**内容を表す語**が効きます |
| **取引先だけ** 入力 | その取引先の請求書はすべて同じ科目へ | **摘要を読んでも内容が分からない請求書**。取引先が分かれば科目も決まる場合 |
| **両方** 入力 | 両方に一致したときだけ適用（もっとも安全） | 同じ取引先でも案件で科目が変わる場合。まずはこの形を推奨 |

**適用は「具体的なルールが勝つ」順序**です。

```
1. 取引先＋摘要の両方を指定したルール   ← もっとも具体的
2. 取引先だけのルール
3. 摘要だけのルール
（同じ具体度なら、条件の文字数が長い＝限定的なほうが優先）
```

登録した順番は関係ありません。**先に一般ルールを作っておいて、あとから個別ルールを足せばそちらが勝ちます。**

#### 摘要に情報が無い請求書の例（北日本カコー）

```
摘要：「前受金として」      ← これだけでは何の費用か分からない
金額：9,750,000 ＋ 消費税 975,000
実際の内容：レーンの費用（固定費・減価償却）
```

このタイプは摘要でルールを作れません。**取引先キーワード**で作ります。

| 取引先キーワード | 摘要キーワード | → 大分類 | → 小分類 | メモ |
|---|---|---|---|---|
| `北日本カコー` | （空） | 減価償却費 | 減価償却費 | レーン設備の費用（固定費） |

「メモ」欄は任意です。**なぜこのルールにしたかを残しておく**と、引き継ぎのときに効きます。

> ⚠ 逆に、摘要キーワードに `前受金` とだけ入れるのは危険です。
> 「前受金として」は他社の請求書にも出てくる一般的な文言なので、無関係な請求書まで
> 同じ科目に仕分けられてしまいます。**摘要が一般的すぎる語のときは取引先で縛ってください。**

初期値として22件のルールを入れてありますので、形はそこを参考にしてください。

### ③ PCA科目の紐付けは「1対1」にこだわらない
社内の小分類を複数まとめて同じPCA科目に紐付けて構いません。
社内用CSVには細かい小分類がそのまま残り、会計事務所用CSVでだけ集約されます。
**細かさを失わずに、提出先には粗く出せる**のがこの構成の狙いです。

### ④ 迷ったらPCA科目は未設定のままにする
未設定なら会計事務所用CSVでは空欄になるだけで、社内用CSVは細かい分類のまま使えます。
**社内管理を先に固めて、会計事務所への紐付けは後回し**にできます。

### ⑤ さらに自動化したくなったら
現在は「キーワード完全一致（部分一致）」ですが、運用が固まってきた段階で
「取引先名＋金額レンジ」「請求書テンプレート単位」などの条件も追加できます。
まずは今の形で使ってみて、手作業が残る箇所が見えてから足すのが確実です。

## 6. 社内管理科目マスタ（「PL（詳細）」D〜E列 実データ）

抽出して初期値に組み込みました。貼り付け作業なしで、すぐ本番の分類で動きます。

|---|---|---|---|
| 売上 | 4 | 飲食 / 物販 / 予約 / その他 | `700 売上高` |
| 原価 | 24 | 飲食→食材原価・版権元RY・BBV飲食フィー<br>物販→商品原価（レッグスフィー含む）・物流費 ほか<br>予約→予約特典原価・レッグス＋HVCフィー ほか<br>共通→版権使用料・デザイン費・施工装飾費 ほか | `710 売上原価` |
| 販管費 | 31 | 旅費交通費・通信費・業務委託費・賃借料 ほか | 個別に紐付け |

除外したもの（科目ではないため）：
- **売上総利益セクション**（計算値）
- **原価セクションのグループ小計行**（飲食／物販／予約／共通の見出し行）

### ⚠ 「版権元RY」は大分類とセットでないと確定できません

`版権元RY` は **飲食・物販・予約の3つの大分類**に同じ名前で存在します。
そのため科目の識別キーは **「大分類＋小分類」のペア**にしてあります。

- AIには大分類と小分類を**必ずペアで**返させています
- 大分類が特定できない明細は、3つのうち1つを勝手に選ばず**空欄**で出力します
- その際「要確認メモ」列に理由が入り、プレビューでは行がオレンジ色になります

### PCA科目コードが空欄の6科目

次の6つは、現行のPCA勘定科目マスタ（79科目）に対応する科目が存在しないため、
**意図的に空欄**にしてあります。会計事務所用CSVでは科目欄が空欄で出力されます。

| 社内科目 | 状況 |
|---|---|
| 本部人件費 | PCAの人件費科目は `759 店舗人件費` のみ。本部分の科目が未定 |
| 福利厚生費 | PCAに該当科目なし |
| 教育研修費 | PCAに該当科目なし |
| 販売促進費 | `742 広告宣伝費` に寄せるか、新設するか要判断 |
| 衛生管理費 | PCAに該当科目なし |
| その他収入支出 | 内容により科目が変わるため固定できない |

紐付け先が決まりましたら、**画面の【⚙ 勘定科目マスタ設定 → 社内管理科目】の3列目にコードを足すだけ**です。
コードの書き換えは不要です。

> なお `賃借料` は PCA の `767 地代家賃` に、`業務委託費` は `758 業務委託・ｺﾝｻﾙ` に、
> `クレジット手数料`・`支払手数料（経営指導料）` は `756 支払手数料` に寄せています。

## 7. 社内の細かい仕訳と会計事務所の科目をどう合わせるか（ご提案）

社内財務管理表の粒度が細かく、PCAの勘定科目は粗い、というギャップは
**「1対1で対応させようとしない」**ことで解けます。3層に分けて持つ構成にしました。

```
  【第1層】社内管理科目（細かい）        大分類 / 小分類
        例：販管費 / 広告制作費、販管費 / 販促イベント費
                    │
                    │  ← マスタの3列目（PCA科目コード）で紐付け
                    ▼
  【第2層】PCA勘定科目（粗い）           742 広告宣伝費
                    │
                    ▼
  【第3層】出力          社内用CSV … 大分類・小分類ごと出力（細かいまま）
                        会計事務所用CSV … PCA科目に集約して出力（粗く）
```

### この構成の利点
1. **AIには社内の細かい小分類だけを選ばせる。**
   窓5のプロンプトには、マスタに登録された大分類/小分類の一覧をそのまま渡しており、
   **一覧に無い科目名を作ることを禁止**しています。表記ゆれが発生しません。
2. **粗い科目への集約はマスタの紐付けが機械的に行う。**
   AIに二重に判断させないので、ブレません。
   複数の小分類を同じPCAコードに紐付ければ、そのまま合算されます。
3. **紐付けが未設定の小分類は、会計事務所用CSVでは科目欄が空欄になります。**
   「勝手に近そうな科目へ寄せる」ことをしないので、事故が起きません。
   マスタ取り込み時に「うち◯件はPCA科目コード未設定」と件数が表示されます。
4. **社内ルールはキーワードで固定できます。**
   `AccountMaster.gs` の `KEYWORD_RULES` に「この取引先は必ずこの小分類」を書いておくと、
   AIの判断より優先されます（初期値としてAmazon・JR・NTTなど12件を入れてあります）。

### 運用の始め方（おすすめ順）
1. まず「PL（詳細）」D〜E列を貼り付ける（3列目は空でOK）
2. 窓5に請求書を数枚流して、社内用CSVで小分類が正しく付くかを確認
3. 確認できた小分類から順に、3列目にPCA科目コードを埋めていく
4. 埋まった分だけ会計事務所用CSVが自動で出力されるようになる

一度に全部を紐付ける必要はありません。空欄のまま出力し、後から書き換える運用が可能です。
