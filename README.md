## 3. 文字化けの原因と修正内容

請求書で文字化けが起きていた原因は、単一ではなく次の5つが重なっていました。

### ① CSVのクォート処理が無かった（最大の原因）
V7.00 は `row.join(",")` でCSVを組み立てていました。
請求書の摘要には「株式会社A, B支店」のようにカンマが入ることが多く、
その1文字で**列が丸ごと右にズレて**、金額欄に文字列が入り込み、
画面上は「文字化け」に見えていました。

→ `CsvUtil`（サーバー）と `Utils.csvRow`（画面）でRFC4180準拠のクォート処理を追加。
読み込み側も `split(',')` をやめ、クォート対応パーサ `Utils.parseCsv` に置き換えました。

### ② Geminiの応答を先頭パートしか読んでいなかった
`jsonRes.candidates[0].content.parts[0].text` としていたため、
請求書のように情報量が多く応答が複数パートに分割されると、
**JSONが途中で切れた状態**でパースされ、壊れた文字列が混入していました。

→ 全パートを連結するよう修正（`GeminiApiClient._extractText`）。
あわせて応答形式を `application/json` に固定し、Markdown枠の混入も防止しています。

### ③ ファイル形式の誤判定
`file.type || 'image/jpeg'` としていたため、MIMEが空のPDFやHEICを
**JPEG画像としてAIに送信**し、AIがバイナリを誤読していました。

→ 拡張子から正しいMIMEを判定し、非対応形式（Excel・CSVなど）は
その場でエラー表示して送信しないようにしました。

### ④ Shift-JISに存在しない文字
請求書に頻出する `①` `㈱` `Ⅲ` `～` `−` や絵文字はShift-JISに存在せず、
変換時に化けます。

→ `Utils.normalizeForSjis` で安全な文字に置換（`①`→`(1)`、`㈱`→`(株)` など）。
さらに画面右上に**文字コード切替（Shift-JIS / UTF-8 BOM付き）**を追加しました。
弥生・PCAのPC版へ取り込む場合はShift-JIS、Excelで開くだけならUTF-8が確実です。

### ⑤ 制御文字・化け跡の混入
Excel由来の `_x000D_`、制御文字、置換文字 `U+FFFD` がそのまま出力されていました。

→ `CsvUtil.sanitize` で除去し、改行は半角スペースに畳んで1明細1行を保証しています。

## 4. 窓5：PCA会計 仕訳変換窓の使い方

1. 窓5に請求書・領収書を**何枚でも**ドロップ（PDF・PNG・JPEG・WEBP・HEIC）
2. 「まとめてAI解析」を押すと1件ずつ順番に解析され、結果が下の表に**蓄積**されます
3. 表の上のボタンで **🏢 社内用** / **🏛 会計事務所用** を切り替え
4. **CSV / Excel / スプレッドシート**のいずれかで出力

> 直列処理にしているのは、同時実行するとGASの実行数制限とGemini APIのレート制限に
> 当たりやすいためです。1枚が失敗しても他の枚数の処理は止まりません。

### 出力レイアウト

**🏢 社内用**（いただいたPCA見本データ `24.LTR…2024.xlsx` の並びに合わせています）

先頭11列は見本と完全に同じ順序なので、社内財務管理表にそのまま貼り付けられます。

```
伝票日付, 伝票番号, 借方科目コード, 借方科目名, 借方補助コード, 借方補助名,
借方部門コード, 借方部門名, 借方税区分名, 借方金額, 摘要文,
大分類, 小分類, 取引先, 元ファイル名
```
- 伝票日付は見本にあわせ `20260105` 形式
- 消費税額が読み取れた場合、`191 仮払消費税等` の行が自動で追加されます（見本と同じ税抜経理の形）

**🏛 会計事務所用**（PCA仕訳インポート想定・借方/貸方ペア形式）

```
伝票日付, 伝票番号,
借方科目コード, 借方科目名, 借方補助コード, 借方補助名, 借方部門コード, 借方部門名, 借方税区分名, 借方金額,
貸方科目コード, 貸方科目名, 貸方補助コード, 貸方補助名, 貸方部門コード, 貸方部門名, 貸方税区分名, 貸方金額,
摘要文
```
- 伝票日付は `2026/01/05` 形式
- 貸方の相手科目は **`420 未払金`** を既定にしています。変更する場合は
  `Code.gs` の `buildOfficeRows()` 内 `CREDIT_CODE` / `CREDIT_NAME` を書き換えてください
- 借方合計＝貸方合計になるよう行単位で対にしています

> ℹ️ いただいた見本は借方側だけを抽出した明細でしたので、**社内用はその並びを忠実に再現**し、
> **会計事務所用はPCAに取り込める貸借ペア形式**を新たに用意する、という切り分けにしました。
> 会計事務所側で指定の受入フォーマットがある場合は、その列順を教えていただければ合わせ込みます。

## 5. 勘定科目マスタの設定（グレーアウト行の扱い）

画面右上の **「⚙ 勘定科目マスタ設定」** から、Excelの列をそのままコピー＆ペーストで登録できます。
タブ区切り・カンマ区切りのどちらでも取り込め、見出し行は自動で除外されます。

| タブ | 貼り付ける列 | 用途 |
|---|---|---|
| 社内管理科目 | 大分類 / 小分類 / (任意)PCA科目コード | 社内用CSVの分類、AIへの選択肢 |
| PCA勘定科目 | コード / 科目名 / 大分類 | 会計事務所用CSVの科目 |
| 部門 | 部門コード / 部門名 | 借方・貸方の部門 |

### グレーアウト行について
いただいた `勘定科目設定.xlsx` を確認したところ、
- `委員会勘定科目` シート … 328行中 **132行がグレーアウト**（＝196行が有効）
- `LTR勘定科目` シート … 327行すべてグレーアウトなし

でした。**グレーアウト行を削除してからコピーして貼り付けてください。**
マスタに載っていない科目は、AIが何を返しても採用されず**空欄**になるため、
「グレーアウト行は使わない」という運用がそのまま担保されます。

> なお、この設定Excelの科目コードは6桁（`00752001` のようなSAP形式）で、
> PCA見本データの3桁コード（`752`）とは体系が異なります。
> 会計事務所提出用は3桁のPCAコードが必要なため、初期値にはPCA見本データ由来の
> **79科目**を入れてあります。6桁体系へ移行される場合は、上記パネルから貼り替えてください。

コード変更は一切不要です。

## 7. 社内の細かい仕訳と会計事務所の科目をどう合わせるか（ご提案）

社内財務管理表の粒度が細かく、PCAの勘定科目は粗い、というギャップは
**「1対1で対応させようとしない」**ことで解けます。3層に分けて持つ構成にしました。

```
  【第1層】社内管理科目（細かい）        大分類 / 小分類
        例：販管費 / 広告制作費、販管費 / 販促イベント費
                    │
                    │  ← マスタの3列目（PCA科目コード）で紐付け
                    ▼
  【第2層】PCA勘定科目（粗い）           742 広告宣伝費
                    │
                    ▼
  【第3層】出力          社内用CSV … 大分類・小分類ごと出力（細かいまま）
                        会計事務所用CSV … PCA科目に集約して出力（粗く）
```

### この構成の利点
1. **AIには社内の細かい小分類だけを選ばせる。**
   窓5のプロンプトには、マスタに登録された大分類/小分類の一覧をそのまま渡しており、
   **一覧に無い科目名を作ることを禁止**しています。表記ゆれが発生しません。
2. **粗い科目への集約はマスタの紐付けが機械的に行う。**
   AIに二重に判断させないので、ブレません。
   複数の小分類を同じPCAコードに紐付ければ、そのまま合算されます。
3. **紐付けが未設定の小分類は、会計事務所用CSVでは科目欄が空欄になります。**
   「勝手に近そうな科目へ寄せる」ことをしないので、事故が起きません。
   マスタ取り込み時に「うち◯件はPCA科目コード未設定」と件数が表示されます。
4. **社内ルールはキーワードで固定できます。**
   `AccountMaster.gs` の `KEYWORD_RULES` に「この取引先は必ずこの小分類」を書いておくと、
   AIの判断より優先されます（初期値としてAmazon・JR・NTTなど12件を入れてあります）。

### 運用の始め方（おすすめ順）
1. まず「PL（詳細）」D〜E列を貼り付ける（3列目は空でOK）
2. 窓5に請求書を数枚流して、社内用CSVで小分類が正しく付くかを確認
3. 確認できた小分類から順に、3列目にPCA科目コードを埋めていく
4. 埋まった分だけ会計事務所用CSVが自動で出力されるようになる

一度に全部を紐付ける必要はありません。空欄のまま出力し、後から書き換える運用が可能です。
