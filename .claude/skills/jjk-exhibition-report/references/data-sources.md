# 入力データの仕様

`extract_data.py` は列位置を決め打ちせずヘッダ文字列から判定するので、通常はここを
読まなくても通る。判定に失敗したときだけ、この資料で構造を確認する。

## 会場ファイル（レジ通過単品売上）

各会場から届く物販日報。シート名は `レジ通過単品売上` 固定。会場ごとに列位置が違う。

### 自動判定のルール

| 項目 | 判定方法 |
|---|---|
| ヘッダ行 `hr` | 4列目が `商品名`、5列目が `JAN` の行 |
| 日付行 `dr` | `hr + 1` |
| 日次列 | ヘッダ行に `1, 2, 3, …` と連番が入っている列 |
| 税込単価 | 日付行が `(税込)` の列 |
| 販売数 | ヘッダ行が `販売数` の列 |
| 販売金額 | 販売数の隣の列 |
| 販売可能数 | ヘッダ行が `販売可能数` の列 |
| 理論上在庫 | ヘッダ行が `理論上` の列 |
| 納品合計数 | ヘッダ行が `納品` かつ 日付行が `合計数` の列 |
| 内覧会 | ヘッダ行が `内覧会` の列（東京のみ） |
| 入場者数 | ヘッダ行より上で `入場者数` ラベルがある行 |

日次列を「連番」で拾うのが肝。東京には日次列の手前に `内覧会`（12/4）の列があり、
日付だけで拾うとこれを会期1日目と誤認する。連番なら確実に会期分だけ取れる。

### 実績で確認した列位置（参考）

| 会場 | ヘッダ行 | 日次開始列 | 日数 | 販売数 | 販売可能数 |
|---|---|---|---|---|---|
| 東京（池袋） | 9 | 14 | 25 | 39 | 65 |
| 名古屋 | 6 | 11 | 19 | 32 | 48 |
| 博多 | 6 | 11 | 26 | 37 | 54 |
| 大阪（梅田） | 6 | 11 | 20 | 31 | 52 |
| 札幌 | 7 | 13 | 20 | 33 | 50 |

### 元データの既知の癖

- **内覧会**：東京の12/4分（全商品計142個）。会場間比較の公平性のため会期実績からは除外する。
- **小数の混入**：名古屋の販売可能数に小数を含む商品が3件ある（1389.6／2265.2／9.6）。
  `build_report.py` が整数に丸める。合計への影響は1個未満。
- **価格改定**：イメージリング8種は東京¥22,000→名古屋以降¥27,500。
  販売金額は必ず**各会場の実売単価**で計算する（⑤シートに会場別の単価列がある）。
- **報告書の総売上との差**：本レポートの物販売上はレジ袋代・音声ガイド・当日券を除いた
  商品売上（税込）なので、会場報告の総売上とは一致しないことがある。

## 実在庫ファイル

`元データ` シート（または1行目が `JANコード(EAN/UPC)` のシート）に保管場所別の理論在庫。

| 保管場所 | 名称 |
|---|---|
| CX01 | CX催事 |
| DB00 | DBS倉庫 |

これに**直近会場の返送良品**（`◯.◯レッグス倉庫検品結果(◯◯返送分)` シートの `良品` 列）を
足したものが実在庫。返送分シートは会場ごとに複数あるため、先頭の「月.日」が最大のものを
自動採用し、採用したシート名を必ず出力する。想定と違えば `--return-sheet` で明示する。

返送良品は各商品の**前会場の会期末残**とほぼ一致するはずなので、大きくズレたら
検品差異か不良控除を確認する（⑧シートの備考に自動で注記が出る）。

## 運営からの欠品報告メール

`.msg` 形式で届く。本文は OLE の `__substg1.0_1000001F` ストリーム（UTF-16LE）。
`olefile` で読める。

```python
import olefile, re
f = olefile.OleFileIO('報告.msg')
for e in ('/'.join(x) for x in f.listdir()):
    if re.search(r'__substg1\.0_1000001F', e):
        print(f.openstream(e).read().decode('utf-16-le'))
```

読み取ったら `config.py` の `SHORTAGE` と `SHORTAGE_REPORT_DATE` を更新する。
「追納困難」等の但し書きも本文どおりに残す（実在庫と食い違うことがあり、
その齟齬自体が依頼者への報告価値になる）。
