呪術廻戦展のLEGS商品分析レポートを再生成してください。

`jjk-exhibition-report` スキルを使い、`references/requirements.md` の仕様どおりに出力します。
仕様を思い出さずに作り直すと過去に指摘済みの論点を落とすので、必ずスキルを読んでから着手してください。

## 引数

$ARGUMENTS

引数には更新内容を書いてください（省略時は下記の手順で確認します）。例：

- `札幌7/28日報追加` — 開催中会場の実績日数を1日増やす
- `石川会場開始 日報3日分` — 会場を1つ進める
- `欠品報告メール受領` — 運営からの欠品報告を反映
- `実在庫7/31時点に更新` — 在庫スナップショットを差し替え

## 手順

1. `.claude/skills/jjk-exhibition-report/SKILL.md` と `references/requirements.md` を読む。
2. 今回受け取ったファイルを確認する。不足していれば、どのファイルが必要かを具体的に聞く
   （各会場の「レジ通過単品売上」xlsx、実在庫xlsx、欠品報告メール）。
   前回から変わらないファイルは、リポジトリや前回のパスをそのまま使ってよいか確認する。
3. `scripts/config.py` の該当箇所を更新する（更新パターンはSKILL.mdに整理済み）。
4. extract → build → recalc → fix_font の順に実行する。
5. 生成物の数値をPythonで独立に検算し、`recalc` が `total_errors: 0` であることを確認する。
6. 変更のあった数値を前回と対比し、要確認事項とあわせてチャットで報告する。
7. `config.py` と `requirements.md` の更新分もコミットする（次回の再現性のため）。

## 注意

- フォントは Meiryo UI。`fix_font.py` は必ず `recalc.py` の**後**に実行する。
- 数式はハードコードせずExcel数式として出す。「前提・入力」シートで再計算できる状態を保つ。
- 前提・仮定・データの不備はシート上に★要確認として明記する。
- 結論は「発注するか / いつまでに / 何を / 何個」まで言い切る。
