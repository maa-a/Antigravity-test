遠藤さんに寄せる業務の整理と、業務フローの設計

7/23 すり合わせMTG と 7/24 通話の議事録から、山崎さんが「遠藤さんがやった方が良い」と述べた箇所と、遠藤さん自身が「自分がやった方が良い」と述べた箇所だけを抜き出し、業務単位に整理したうえで、業務フローを文章と図で組み立てたもの。対立・押し問答の切り口は対象外。

作成 2026/8/5 出典 2026/7/23 すり合わせMTG・2026/7/24 通話 用途 次回協議の準備

結論から

山口さんが議事録中で唯一はっきり同意した集約の形は、山崎さんが提案した「西田さん＝ポップアップ／遠藤さん＝常設＋地域化」の住み分け。これに対し山口さんは「めっちゃいいと思います」「ベースは私も超アグリです」と明言している。

したがって次回は「MDを遠藤さんに寄せてください」ではなく、「同意いただいた住み分けを実装します」という立て付けで入る。あわせて、山口さんが動く条件として本人が明示した「切り方のルール案の先出し」を持ち込めば、議論は前に進む。

反対理由の中核である「カフェは伝票の数が桁違い」に対する回答は、仕訳入力データ生成アプリ（借方は会計事務所用に作成済み）。貸方データ・財務管理表用出力も追加機能で対応可能であることを示せば、負荷論はそのまま解消する。

一気通貫で全部を遠藤さんに集約したいというところが委員会メンバーとしての意向。MDだけ切り出すのではなく、全部をまとめて遠藤さんにお願いすればそれが正しく適切に処理されていくよね、というところで黒田さんに調整をお願いしていた
A-8　支払い

委員会のお財布からお金を出すときはワークフロー承認をして、Teamsのチャット上で経理の小日向さんとも連携して処理する。その小日向さんとの連携と、そこでやった処理を会計事務所に報告する連携を遠藤さんにやっていただくというところが決まっている
A-9 / A-10　窓口
MDを含めた集約と依頼窓口の一本化
よしなにやることを、MDも含めて遠藤さんにお願いしたかった／営業からすると、委員会の財布から払うものは遠藤さん、MDのものは西田さん、と判断して分けて依頼しなきゃいけなくなる。またチャットの場所も変わる。それをやめたいというのがこちらの希望
A-11　運用品質
問い合わせを発生させない状態づくり
浦野さんから西田さんに金額ズレの理由の問い合わせが発生しているチャットを拝見している。コナンでもその可能性がある。帳票を見せればズレについて分かる状態にしたかったし、そもそも問い合わせもなるべく必要がない状態に仕上げたかった
A-12　体制　★山口さん同意
西田さん＝ポップアップ／遠藤さん＝常設
できる人が2人いるとなった場合、緻密さが要る常設と、今までのやり方を守れるポップアップで人が分かれられるのなら、地域化も含めて遠藤さんがやるとしてしまえば、常設としてはそこに一本化される。LTRとしては2本かもしれないが、事業部ごとに見ればみんな一つの人に依頼できてシンプル
→ 山口さん「めっちゃいいと思います」「今のアイディアはベースは私も超アグリです」

B．遠藤さん自身が「自分がやった方が良い」と言っている箇所

B-1 / B-2　思想
社内のお金回りを全て把握する役割
管理会計向けにやっていくだけとかではなく、社内のお金回りの動きは全て私が把握する――これを実現させていきたいというのが思想／通常でいま管理できていないところをコナンではきちんとやっていかなければならない。そこに集約したことによって私が把握できなくなってしまうのは困る。それを担いたいというところで入ることになっていた
B-3　窓口
依頼窓口を常設チャットに一本化
今ある業務依頼チャットにコナンの依頼が入ってくることは、今後基本的にはないようにしようと思っていた／私宛のもの、羽渕さんや西田さん宛のものがその中に含まれてしまうのは営業としては厳しい。営業が誰に何を依頼しなければいけなかったのかを把握するのは非常に困難
B-4 / B-7　フローの核心
按分・在庫区分を「発注段階」で確定
按分は現時点では締めが終わってからの対応を西田さんがされていると伺っているが、その対応は踏まないというふうにやらなければならないので、発注の段階できちんとする処理を対応していくというフローに、コナンは変えていく予定／非在庫を最初にゴンと切ってしまうのは、コナンについては最初からもうやめていきたい
B-5　役務の定義
フロー変更を営業側に着地させる
営業が今まで通りにやったとして混乱しないのか、非在庫リストに記載しないことに対して対応が可能なのか、ができなくなってしまうのであれば、一気通貫していたとしても意味をなさない。なのでそこをきちんと対応できる人材が間に入っている必要があるという役務として私がいる
B-6　反論の骨格
営業管理の複線化は問題ない
マネジメント周りは確かにそういうことがあると思うが、営業管理はそうではないと私は思っている。同じ人が別々の事業部の担当をしているというのは複数にしてあり得るので、私の依頼が誤らなければ問題ない。私が依頼する指示が間違えばお金も数字も間違うので、そこが問題なければ営業管理については問題ない
B-8　負荷論
実務負荷を判断材料に入れる
やり直すのは実務処理をする側じゃないですか。判断をされるのは山口さんかもしれないが、実務処理をするのは実務処理する側が対応する。その負荷がどのぐらいのものかやられてきたのでお分かりだと思う。なのでそういったことを減らす方向にしなければならないのではないか
B-10 / B-11　前提
数字は既に集まる／やり方の主導権
私に数字がめっちゃくちゃくる。髙山さんですら私に間に入ってもらってやってもらうと発言していたと聞いて、より数字が入ってくるので、私と連携しないわけにいかない／委員会の締め処理は、責任者が誰であっても依頼元は営業側である以上、やり方はこちらに沿ってもらう
7/24 通話
追加方針（7/25 以降）
実現手段まで自分で持つ
遠藤がMDもやれば西田さんは楽になる想定。欲しいデータも遠藤が準備して渡す。日報のまとめも要らず、取り込みたい内容を提示すればそのように出力してデータを渡す。システムアプリの構築も遠藤が行い、希望を伺い仕様も決められるものを作成。借方用の仕訳入力データは会計事務所用に作成済み。追加機能という形で貸方のデータや財務管理表用の出力も対応可能

D．業務フロー ①　委員会口座からの支払い　合意済み

山口さん「委員会の処理の流れは今めちゃめちゃ理解できて、常設のチャットでやるのは超合理的だなと思いました」「全然アグリでございます」。ここは動かせる。

  1. 営業が発注を起案する（初期投資・什器・書き下ろし費用など）。
  2. ワークフロー承認（髙山さん設計）を通し、委員会の意思決定として承認を取る。
  3. 承認後、Teams の常設コナン専用チャットに集約。会計事務所もここに参加する。
  4. 遠藤さんが経理・小日向さんと連携し、委員会名義の銀行口座から支払いを実行する。※LTR口座ではないため、既存のLTRフローでは物理的に処理できない
  5. 遠藤さんが処理内容を会計事務所へ報告・連携（証憑・按分・勘定科目の指定を含む）。
  6. 会計事務所がPCA会計へ仕訳入力。
  7. 月次で試算表を作成し、5営業日以内に委員会へ提出。同じ数字を3つのPLの突合に回す。

E．業務フロー ②　MD（物販原価）の現行フロー　山口さんが維持を主張

  1. 協力先から最終見積が出る。
  2. SCM が受領し、事業部担当（営業）に「最終金額はこれでいく」と連携。営業が自分の収支計画に収まっているかを確認する。※最終見積そのものと収支計画の突合は、最後は誰も確認していない（山口さん認証）
  3. SCM／FE部が仕入伝票を切り、ビジネスアシスタント（渡辺さん）へ依頼。
  4. ビジネスアシスタントのフィルターを通って営業管理（西田さんライン）へ情報が流れる。
  5. 営業管理が計上。原価は一旦非在庫で一括計上され、後から在庫へ振り替える。
  6. 締め後に西田さんが按分を対応。
  7. 財務管理表（LTR全体の経営判断帳票）に集約される。

F．業務フロー ③　提案フロー（遠藤さんへの集約）

現行フローを壊さない。壊すのではなく、「非在庫で切って後で直す」を「発注時点で確定させる」に前倒しするだけ。その前倒しを担う人として遠藤さんが入り、西田さん・経理へは完成したデータを渡す。

  1. 営業からの依頼は常設コナンチャット1本に集約する。営業が「これは委員会財布だから遠藤さん、これはMDだから西田さん」と判断・仕分けする必要をなくす。仕分けは遠藤さんが行う。
  2. 遠藤さんが発注段階で、在庫／非在庫の区分・按分（固定費・共通費）・品目コード・委員会／LTRの帰属を確定させる。
  3. 確定内容を加工済みデータとして配布する。
    • 西田さん・営業管理へ … 取り込みたい形式のまま出力したデータを渡す。日報のまとめは不要。取り込むだけになる。
    • 会計事務所へ … 仕訳入力データ（借方はアプリで生成済み、貸方は追加機能で対応可能）。
    • 経理へ … 支払データ。委員会・ショープロ・東急レクへ … 提出帳票。
  4. 在庫・入出庫は高田くん・佐々木さん・阿部さんと連携し、遠藤さん側で整合を取る。
  5. 月次で3つのPLを突合し、5営業日以内に試算表を委員会へ提出。帳票を見ればズレの理由が分かる状態にし、問い合わせ自体を発生させない。

I．反対理由への回答

山口さんの主張回答材料
コナンに関して全部遠藤さんに集約するのは最適だと思っていない。LTRのフローに乗っ取れないから委員会は銀行口座が別で、LTRのフローでは物理的に処理できない。委員会分の常設チャット処理は山口さん自身が「超合理的」と合意済み。
社内で完全にワンオペになる。経理に二股で業務が来ると困る。マネジメントラインが複数だと面倒マネジメントラインと営業管理は別（B-6）。A-12の住み分けなら依頼者から見た窓口は各1本で、ワンオペも二股も発生しない。山口さん自身が「超アグリ」。
カフェは伝票の数が他の事業部と桁が違う桁が違うからこそ締め後の按分・振替をやめて発注段階で確定すべき。加えて仕訳入力データはアプリで自動生成済み（借方）、貸方・財務管理表出力も追加対応可能。伝票量は遠藤さん側で吸収でき、西田さん・経理の負荷はむしろ下がる。
非在庫で切ってもあとで在庫に振り替えればいい。大した話じゃないやり直すのは実務処理側（B-8）。振替は労力が大きく、5営業日の委員会報告と両立しない。
全体最適のため、まずは今のフローに乗ってやって、裏の事情を知ってほしい承諾したうえで期限を切る。「今のフローに乗る」のは7月分（非在庫処理）まで。8月以降のルール確定に向けた協議の場を設定する ── 山口さん自身が「その内容を詰めるときにご協力いただきたい」「そういう時間を設けたい」と要請している。

J．次回に持ち込むもの

  1. 在庫／非在庫・按分の切り方ルール案（先出し） ── 山口さん「ルールだけ先に上げてもらいたい。切り方だけ合意形成が取れれば、それで切る」。相手が動く条件を本人が明示している。
  2. アプリのデモ ── 借方の仕訳入力データは会計事務所用に作成済み。貸方・財務管理表出力は追加機能で対応可能。「伝票の数が桁違い」への直接の回答になる。
  3. 体制図（G） ── 山口さん同意済みの案として提示する。
  4. 7月発生分の一覧 ── ハイゼンレーン頭金（7月末締め8月末払い）、書き下ろし費用、サンプル費用、デザイン費、英文確認費など。山口さんから確認依頼あり。
  5. 固定費按分ルール協議への参加 ── 地域化・成瀬くんと同時進行。山口さんから協力要請あり。

なお 7/24 通話で確認された前提として、話し合いの冒頭で「委員会の締め処理は、責任者が誰であっても依頼元は営業側であり、やり方はこちらに沿ってもらう」という点を前田さん経由で握っておくこと。ここが握れているかどうかで展開が変わる、というのが遠藤さんの見立て。
